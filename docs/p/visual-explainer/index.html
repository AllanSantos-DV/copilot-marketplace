visual-explainer

v0.8.0

O visual-explainer transforma um pedido em texto — "explica o ciclo da água", "o motor 4 tempos", "o fluxo HTTP", "como funciona uma tecla mecânica" — numa página HTML autocontida e offline, com narração por voz, câmera passo a passo, play/pause, zoom e peças clicáveis. Você não desenha nada: um agente desenhista escreve uma spec declarativa, o builder assa a voz pelo motor (vox-engine) e entrega o HTML pronto, aberto no navegador — ou, se você pedir, um vídeo MP4 com a mesma voz e legendas.

    Peça um vídeo e a mesma explicação sai como MP4: uma trilha única com as falas do vox-engine, legendas e cada passo durando o tempo da sua narração. A renderização é determinística (o mesmo pedido gera o mesmo vídeo) e leva alguns minutos, com o progresso visível no build. Para vídeos de produto, presets prontos fixam cenas, layout e tempo: você só preenche textos curtos.

  • Do pedido à página, sem desenhar

    Você descreve o assunto; o agente escolhe o motor, escreve a spec em JSON e o builder monta o HTML. Nada de arrastar formas na mão.

  • Câmera passo a passo + vista explodida

    A câmera navega, foca e revela uma ideia por vez, com auto-enquadramento. Para aparelhos, a vista explodida desmonta em camadas (abstrato em placas, ou peças com forma real) e explica cada uma.

    Play/pause que retoma de onde parou, velocidade, zoom e peças clicáveis — clicar numa peça toca a explicação dela. Atalhos de teclado (Espaço, setas, [ ]), link direto para um passo e preferências lembradas.

#O que é

O visual-explainer é um agente desenhista para o GitHub Copilot. Você pede uma explicação visual de um assunto e ele entrega uma página HTML autocontida que anima e deixa você interagir com o conceito — abrir, pausar, acelerar, dar zoom e clicar nas peças.

O truque é não desenhar na mão. O agente escreve uma spec declarativa (JSON) descrevendo o que mostrar, e um builder monta o HTML otimizado, inlinando o motor certo. O resultado é um arquivo único, offline, que abre no seu navegador.

Por baixo, quem monta tudo é o motor vxk: um servidor MCP independente do Copilot, publicado no engine-registry e instalado uma vez por máquina em ~/.vxk. O plugin só garante o motor, declara o servidor vxk e traz o agente — o mesmo motor serve Claude Code, Codex ou qualquer cliente MCP.

i

O agente é instalado no arranque. Depois de instalar o plugin, reinicie o app uma vez para o agente visual-explainer aparecer no seletor.

#Como usar

  1. Instale o plugin

    Pelo marketplace, com o comando da seção Instalar abaixo.

  2. Reinicie o app

    Uma vez, para o agente desenhista ser descoberto no seletor.

  3. Peça uma explicação

    Selecione o agente visual-explainer (ou peça uma explicação visual) e descreva o assunto: "explica visualmente o modelo atômico de Bohr".

  4. Abra a página

    O agente escolhe o motor, escreve a spec, roda o builder e abre a página no navegador. Os arquivos ficam em Desktop\visual-explanations\.

#Dois motores para dois tipos de arte

Nem toda explicação pede o mesmo motor. O builder inlina o certo para o caso, e o agente raramente desenha do zero — um design system de componentes reutilizáveis cresce a cada arte.

  • Motor vxk (leve, próprio) — para as explicações comuns: órbitas, física, fluxo, algoritmos, linhas do tempo. É o caminho padrão.
  • Motor konva (vendorizado) — para grafos e redes: cada nó mostra o papel (ícone + subtítulo) e cada ligação o que trafega; ao clicar, o nó e os vizinhos acendem, a lateral lista com quem ele fala e a narração daquele nó toca.
i

Performance vem embutida: ~30 FPS, DPR limitado a 1.5 e pausa automática quando a aba fica oculta. Tudo offline e num único arquivo.

#Narração por voz, câmera e vista explodida

As explicações não são só desenho: elas falam. O builder assa a narração de cada passo pela voz do motor vox-engine e embute o áudio no próprio HTML — a página conta a história enquanto anima.

  • Narração assada — a página nasce com voz; se o motor não estiver disponível, o build falha em vez de entregar mudo.
  • Legenda e lateral — o texto de cada passo aparece na barra lateral e, com CC ligado, como legenda junto do áudio.
  • Câmera passo a passo — a câmera navega, dá zoom e foca uma ideia por vez, com auto-enquadramento que preenche a tela.
  • Vista explodida — para aparelhos: o objeto se desmonta em camadas e a câmera explica cada uma. Conceitos abstratos viram placas; objetos físicos ganham a silhueta real da peça.
  • Design system rico — cards com ícone Lucide, diagramas de sequência com mensagens que viajam entre os lados, conectores que se desenham, medidores e um catálogo que cresce a cada arte.
i

Requer o motor de voz vox-engine instalado (o mesmo do plugin de voz). O áudio é assado no build e fica embutido — a página toca offline.

#Como funciona

  • Pedido — você descreve o assunto para o agente desenhista.
  • Catálogo — pelo MCP vxk (vxk_guide, vxk_catalog), o agente lê os componentes e exemplos prontos e acha o ícone de cada conceito pela busca nos tags oficiais do Lucide: ele compõe a biblioteca, nunca desenha do zero.
  • Spec + validação — escreve a spec em JSON e a confere com vxk_validate (componente, ids, ícones e trecho sem narração) antes de gastar voz.
  • Build — vxk_build assa a narração pelo vox-engine e monta o HTML autocontido (job assíncrono; vxk_build_result acompanha). A spec fica salva ao lado do HTML, para ajustar e rebuildar sem reescrever tudo.
  • Abre — vxk_open abre a página no navegador, com o controle único de reprodução, zoom e peças clicáveis.

Como a saída é um HTML único e offline, você pode guardar, abrir de novo ou compartilhar a explicação sem depender de nada — nem do agente, nem da rede.

i

Vídeo: peça "em vídeo" ou "em MP4" e o agente usa o mesmo fluxo com vxk_build + target:"mp4" (motor vxk, explicações em passos). O MP4 sai com a mesma voz e legendas; vxk_build_result mostra o progresso da renderização e vxk_open abre o arquivo.

Vídeo por preset: para apresentar uma funcionalidade ou um produto, há vídeos prontos — funcionalidade, tour-produto, antes-depois, passo-a-passo e resumo-executivo. O preset já decidiu cenas, layout, voz, legendas e o tempo de cada cena; você só escreve textos curtos e uma fala por cena num JSON. A entrada é validada antes de gastar voz, com todos os problemas de uma vez.

vxk presets                         # lista os presets
vxk presets passo-a-passo           # campos, limites e um exemplo completo
vxk video --preset passo-a-passo --input dados.json

Pelo MCP, as mesmas operações são vxk_presets (lista ou detalhe) e vxk_video (preset + input), acompanhadas por vxk_build_result.

#Perguntas frequentes

As páginas têm áudio?

Sim. Cada explicação nasce narrada: o builder assa a fala de cada passo pela voz do motor vox-engine e embute o áudio no HTML. A página fala ao abrir e roda offline. Requer o vox-engine instalado; sem ele, o build falha em vez de entregar mudo.

Dá para gerar um vídeo em vez da página?

Sim. Peça em vídeo/MP4: a explicação em passos é renderizada como MP4 com a mesma narração do vox-engine e legendas, cada passo durando o tempo da sua fala. Leva alguns minutos; o progresso aparece no build. Grafos (motor konva) e boards continuam só como página.

O que é um preset de vídeo?

Um vídeo pronto para apresentar uma funcionalidade, um produto, um antes e depois, um passo a passo ou um resumo executivo. Cenas, layout, voz, legendas e duração já estão fixos: você preenche só textos curtos num JSON e o render sai sem o agente desenhar nada — por isso é o caminho mais barato para um MP4.

Dá para explicar como um aparelho é montado?

Sim, com a vista explodida: o objeto se desmonta em camadas e a câmera explica cada peça, remontando no fim. Conceitos abstratos (como uma pilha de protocolos) viram placas; objetos com forma física (uma tecla, um aparelho) ganham a silhueta real de cada peça.

Preciso saber desenhar ou animar?

Não. Você descreve o assunto em texto; o agente escreve a spec e o builder monta a página. Você recebe o HTML pronto, animado, narrado e interativo.

A página depende de internet para abrir?

Não. O builder inlina o motor escolhido, então a página é um único HTML autocontido que roda offline no seu navegador. Você pode guardar e reabrir quando quiser.

Qual a diferença entre os motores vxk e konva?

O vxk é o motor leve próprio, para explicações em passos (órbitas, física, fluxos, protocolos, algoritmos). O konva é para grafos e redes: nós com o papel de cada um, ligações rotuladas e destaque dos vizinhos ao clicar. Os dois narram; só o vxk tem coreografia de passos.

Onde ficam as páginas geradas?

Em Desktop\visual-explanations\. Cada explicação vira um arquivo HTML autocontido nessa pasta.

Por que preciso reiniciar o app depois de instalar?

No arranque, o plugin garante o motor vxk e instala o agente desenhista em ~/.copilot/agents (idempotente, por versão). O reinício é para o app descobrir o agente visual-explainer no seletor; o servidor MCP vxk já vem declarado no plugin.

Onde mora o código do plugin?

O motor (servidor MCP, builder, componentes e ícones) é publicado no engine-registry e instalado em ~/.vxk, assinado e verificado. Este plugin é só o cliente fino do Copilot: garante o motor, declara o MCP vxk e traz o agente.

Dá para usar fora do Copilot?

Sim. O motor vxk é um servidor MCP comum: registre node ~/.vxk/bin/vxk-mcp.mjs no Claude Code, no Codex ou em qualquer cliente MCP e use as mesmas tools vxk_*.

Como o motor se atualiza?

Sozinho. No Copilot, o arranque do plugin confere o engine-registry; em qualquer outro cliente MCP, o próprio servidor confere depois de subir e instala a versão nova (verificada por SHA-256 e assinatura), que vale no próximo arranque. VXK_NO_AUTOUPDATE=1 desliga.
